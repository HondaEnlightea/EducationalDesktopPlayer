# EDP（Educational Desktop Player）開発指示書

あなたは、Windowsデスクトップアプリケーション開発、UI/UX設計、ソフトウェアアーキテクチャに精通したシニアエンジニアです。

既存のリポジトリを確認し、以下の要件に基づいてEDPを実装してください。

本アプリケーションは、PC画面の右下に常駐し、ユーザーが別の作業を行いながら学習できるデスクトップ学習支援アプリケーションです。

単なるモックアップではなく、実際に起動・操作・利用履歴の保存ができるMVPを完成させてください。

なお、学習内容や機能を独自に追加・変更することは避け、以下の仕様を厳守してください。

---

## 1. プロジェクト概要

### アプリケーション名

EDP（Educational Desktop Player）

### コンセプト

PCでの通常作業と並行して、画面右下で学習を継続できるデスクトップ常駐型アプリケーション。

学習を始めるために別の大きなアプリケーションを開く必要をなくし、日常的なPC利用の中に学習機会を組み込む。

### 基本方針

* Windows 10/11を対象とする。
* 画面右下に小型ウィンドウとして常駐する。
* 他のアプリケーションの操作を妨げない。
* 学習モードは以下の3種類に限定する。
* 利用履歴をローカルに永続保存する。
* ゲーム要素は実装しない。
* 学習コンテンツとアプリケーション本体を分離する。
* 将来的な学習分野の拡張を考慮する。

---

## 2. 学習モード

以下の3モードを実装する。

### Mode 1：短文モード（Short Sentence Mode）

#### 目的

TOEIC Part 5に関連する英語能力の学習。

対象とする能力は以下。

* 英単語の意味
* イディオム
* 慣用表現
* 文法・語法
* 文中における語句の意味や用法

#### 学習サイクル

以下を繰り返す。

**Step A：英文表示**

英語の1〜2文を表示する。

初期表示では、和訳や解説を表示しない。

**Step B：和訳・解説表示**

ユーザーの操作によって、以下を表示する。

* 英文
* 日本語訳
* 必要に応じた重要語句・イディオム・慣用表現の解説

重要な語句や表現については、英文中の該当箇所をマーカー等で強調できる構造とする。

**Step C：次の英文へ**

次の英文へ進み、同じサイクルを繰り返す。

#### UI要件

* 英文を読みやすい文字サイズで表示する。
* 和訳の表示・非表示を切り替えられる。
* 前後の問題へ移動できる。
* 現在の問題番号を表示する。
* 表示中の英文を誤って読み飛ばさないよう、回答表示と次問題への操作を区別する。

---

### Mode 2：読解モード（Reading Mode）

#### 目的

TOEIC Part 6・7に関連する読解能力の学習。

特に以下を重視する。

* 接続詞の意味と機能
* 文と文の論理的なつながり
* 指示語の参照先
* 文章の展開・構造
* 前後の文脈から意味を読み取る能力

#### 学習サイクル

**Step A：英文表示**

英語の2〜4文を表示する。

初期表示では和訳や解説を隠す。

**Step B：和訳・解説表示**

ユーザーの操作により、以下を表示する。

* 英文
* 日本語訳
* 必要に応じた接続関係や文章構造の解説

#### マーカーによる強調表示

英文の特定箇所を視覚的に強調できるようにする。

強調対象の例：

* 接続詞
* 指示語
* 重要な語句
* 文脈理解の鍵となる表現

マーカーの色や種類は、将来的に複数の意味を持たせられる構造にする。

ただし、初期実装で複雑な注釈エディタを作る必要はない。

コンテンツ側で強調対象を指定できるデータ構造を用意し、表示側で反映すること。

#### UI要件

* 2〜4文をひとまとまりの文章として表示する。
* 文ごとの改行や段落構造を維持する。
* 英文と和訳を対応させて表示できる。
* 強調表示が視認しやすい。
* 文章全体の流れを読みやすいレイアウトとする。
* 前後の文章へ移動できる。

---

### Mode 3：単語帳モード（Flashcard Mode）

#### 目的

表面と裏面を持つ学習カードを表示する汎用機能。

初期段階では少量の英単語サンプルデータのみ用意する。

ただし、将来的には電磁気学などの他分野の公式集にも転用する。

そのため、英語専用のデータ構造にしないこと。

#### 学習サイクル

**Step A：表面表示**

単語や用語、公式などの表面情報を表示する。

**Step B：裏面表示**

ユーザーの操作によって、意味や説明などの裏面情報を表示する。

**Step C：次のカードへ**

次のカードへ進み、同じサイクルを繰り返す。

#### データ構造

最低限、以下の情報を保持できる設計とする。

* 一意なID
* 表面の内容
* 裏面の内容
* 分類・カテゴリ
* 任意の補足説明
* 任意のタグ

表面・裏面は単純な文字列に限定せず、将来的に数式や複数行の説明を扱える構造を検討する。

例えば、以下のようなデータを扱えること。

| 分野   | 表面       | 裏面                        |
| ---- | -------- | ------------------------- |
| 英語   | maintain | 維持する、保つ                   |
| 電磁気学 | ガウスの法則   | 電束密度の面積分と電荷の関係            |
| 数学   | オイラーの公式  | \(e^{ix}=\cos x+i\sin x\) |

上記はデータ構造の説明例であり、初期コンテンツとして大量に用意する必要はない。

#### 拡張性

将来的に以下を追加できる構造が望ましい。

* 分野ごとのカードセット
* JSONによるカードのインポート
* 数式表示
* 画像添付
* カードセットの切り替え

ただし、初期MVPではインポート機能や画像編集機能を必須としない。

## 3. 利用履歴の記録

ゲーム的な報酬システムは実装しないが、ユーザーの利用状況を把握できるようにする。

### 記録対象

* アプリケーションの起動日時
* 利用終了日時
* 利用時間
* 利用した学習モード
* 各モードの表示回数
* 各モードで閲覧したコンテンツのID
* コンテンツごとの閲覧日時
* 和訳・裏面を表示した回数
* 学習セッションの開始・終了

### 記録上の注意

「表示したこと」と「理解したこと」を混同しない。

ユーザーが正解した、習得したなどの情報を、明示的な操作なしに推定・記録しないこと。

### 履歴表示

設定または履歴画面から、以下を確認できるようにする。

* 本日の利用時間
* 累計利用時間
* モード別利用時間
* モード別の閲覧回数
* 最近利用した日時

履歴はローカルに保存し、アプリケーションを再起動しても保持する。

履歴の削除機能も用意する。

## 4. デスクトップ常駐機能

本アプリの主要な特徴であるため、優先度を高く設定する。

### 表示仕様

* 初回起動時に画面右下へ配置する。
* Windowsのタスクバーと重ならないようにする。
* 小型のフローティングウィンドウとする。
* タイトルバーを排したモダンなデザインとする。
* Always on Topに対応する。
* ウィンドウ位置・サイズを変更できる。
* ディスプレイの解像度変更に対応する。
* 画面外にウィンドウが取り残されないようにする。

### 操作仕様

* 通常表示
* コンパクト表示
* 一時非表示
* 再表示
* タスクトレイからの終了

別のアプリケーションを操作する際、EDPが不必要にフォーカスを奪わないこと。

クリック透過機能は実装可能であれば対応するが、操作不能になるリスクを避けることを優先する。

## 5. UI/UXデザイン

### デザイン方針

「学習に集中できる、静かでコンパクトなインターフェース」

ゲーム風の演出や装飾を中心とせず、学習コンテンツの可読性と操作性を最優先とする。

* モダンなデスクトップウィジェット
* 適度な角丸
* 明瞭なタイポグラフィ
* 落ち着いた配色
* 控えめなアニメーション
* 情報の階層が明確なレイアウト

### メイン画面

* EDPの名称
* 学習モード切り替え
* 学習コンテンツ表示領域
* 表示・非表示切り替え
* 前後移動
* 設定・履歴への導線

### モード選択画面

以下の3種類を明確に区別する。

* 短文モード
* 読解モード
* 単語帳モード

モードごとの学習データや表示形式が混在しないようにする。

## 6. 技術・アーキテクチャ

まず既存リポジトリを調査する。

既存の技術構成がある場合は、合理的な理由がない限り維持する。

新規構築の場合は、Electron + React + TypeScript、またはTauri + React + TypeScriptを候補とする。

技術選定では、以下を重視する。

* Windowsでの安定動作
* 透過ウィンドウ
* Always on Top
* タスクトレイ
* ローカルデータ保存
* ビルド・配布の容易さ

### 責務の分離

以下を分離して設計する。

* デスクトップウィンドウ制御
* UI表示
* 学習モードの進行制御
* 学習コンテンツ管理
* 利用履歴管理
* 設定管理

短文モード、読解モード、単語帳モードの共通処理は再利用可能な構造にする。

特に、将来の学習分野追加に際して、アプリケーション本体を大幅に変更せずに済む設計を目指す。

## 8. 実装上の制約

以下を厳守すること。

1. 指定していない学習モードを独自に追加しない。
2. ゲーム要素、ポイント、キャラクター育成、報酬システムを実装しない。
3. 学習内容の難易度や出題方針を独自に決めない。
4. 初期データは機能検証に必要な少量にとどめる。
5. 単語帳モードを英語専用に設計しない。
6. 利用履歴と学習成果を区別する。
7. 実装していない機能を実装済みと報告しない。
8. UIだけを作って学習機能を未実装のまま終了しない。
9. 既存コードを変更する際は、既存機能への影響を確認する。
10. 重大な仕様上の問題がない限り、合理的な判断で実装を進める。

## 9. 完成条件

* Windows上で起動できる。
* デスクトップ右下に常駐できる。
* 短文モード、読解モード、単語帳モードが利用できる。
* 各モードで表示と解説の切り替えができる。
* 前後のコンテンツへ移動できる。
* 読解モードでマーカーによる強調表示ができる。
* 単語帳モードが汎用的な表裏カード構造になっている。
* 利用履歴が永続保存される。
* 履歴を確認・削除できる。
* READMEに起動方法が記載されている。

最終報告では、実装内容、技術構成、起動方法、動作確認結果、未実装事項を明確に提示すること。

**本プロジェクトの目的は、余計なゲーム性を付加することではなく、ユーザーが日常的にPCを利用する時間を、自由度の高い学習機会へ変換することである。**
